# Documentation archive

These files preserve branch-level history and earlier implementation plans. They are not current setup instructions or the source of truth for product behavior.

Use the maintained documents instead:

- `README.md` for setup and architecture.
- `DEVELOPMENT_LOG.md` for the chronological engineering narrative.
- `docs/critical-journeys.md` for the tested access contract.
- `docs/legacy-and-roadmap-inventory.md` for preserved prototypes and compatibility decisions.

The archive remains in Git so earlier reasoning can still be inspected without cluttering the repository root.

The two weighted-tagging files are an identical historical duplicate; both remain, with explicit filenames, until archive deletion is approved.
